# Reports

Use this directory for one-off analysis outputs that inform planning or implementation.

Examples:
- audit findings
- compatibility matrices
- design option comparisons
- implementation reports

Reports are not durable requirements. If a report creates or changes accepted scope, update `planning/requirements.md`, a detailed requirement file, or `planning/backlog.md`.

Name reports with the related backlog id when possible, for example:

- `b3-dist-audit.md`
- `b4-installer-design.md`
