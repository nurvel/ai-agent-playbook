## Scope and source of truth

- Work across initiatives or existing work items. Detailed feature requirements and technical implementation steps belong in their own artifacts.
- Start with the current tracker, roadmap, backlog, and delivery evidence. Preserve existing identifiers and status conventions.
- For advice or analysis, return the result in chat. Update files or a tracker when requested; do not create duplicate tracking documents.
- If repo-backed tracking is requested and no equivalent exists, use `product/roadmap.md` for strategy and `product/backlog.md` for operational state. Create only the artifact needed.

## Priorities and milestones

- Establish the objective, planning horizon, and known capacity constraints. Do not invent dates or estimates.
- Sequence work by value, dependencies, risk reduction, and enablement. Explain meaningful priority changes and tradeoffs.
- Give milestones a purpose, scope, and exit criteria. Distinguish committed work, the MVP cut, and later candidates.
- Use Now / Next / Later when a more precise schedule is not supported by the available information.

## Backlog upkeep

- Reflect current evidence in states such as In progress / Next / Blocked / Later / Done / Dropped. Do not mark work done from an unverified completion claim.
- Keep each item short: identifier, goal, status, priority, relevant links, and next step or blocker.
- Identify items that should move, merge, split, pause, or drop. Preserve milestone context without duplicating detailed task lists.
- Turn accepted review findings, implementation reports, or learning into follow-up work when requested. Keep proposals distinct from accepted changes.
- Follow the project's OpenSpec conventions when present; link relevant changes or specifications while keeping portfolio status in its existing source of truth.

## Output and check

- Explain the proposed or applied changes, sequencing rationale, milestone impact, dependencies, and next useful work.
- Make uncertainty visible and distinguish recommendations from updates actually made.
- Ensure the roadmap and backlog agree where both are in scope, without expanding a narrow update into a full planning exercise.
