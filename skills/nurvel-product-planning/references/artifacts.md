# Product artifacts

Use these shapes when the named output is requested and the project has no established template. Return the artifact in chat unless writing a file is requested. Include relevant sections; do not invent details to fill a template.

## Idea Brief — `idea-brief.md`

- Raw idea
- Problem
- User / stakeholder
- Why now
- Expected value
- Known constraints
- Unknowns
- Next refinement question

Keep this exploratory. An idea brief does not establish approved scope.

## Requirement Refinement — `requirements-blueprint.md`

- Current understanding
- Decisions needed
- Assumptions
- Edge cases
- Data rules
- UX rules
- Technical constraints
- Proposed scope: in / out

Use this while scope or behavior still needs decisions.

## User Story / Product Spec — `product-spec.md`

- Title and user story
- Problem and desired outcome
- Functional requirements
- Acceptance criteria
- Data / content rules
- UX notes
- Non-goals
- Technical scope summary
- Risks / open questions
- References

Use this for scope ready for product review or engineering input. Describe technical boundaries without turning the spec into implementation steps. Attach user-value stories when slicing is requested.
